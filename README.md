# 网申助手 3.9.1 — 模块化基础框架

网申表单自动填写插件（Chrome / Edge）。运行时资料保存在本机浏览器里。当前源码不包含个人简历、照片、API 配置和备份；历史提交不受本次清理影响。

## 下载与使用

[直接下载最新版源码 ZIP](https://github.com/875259680-arch/wangshen/archive/refs/heads/main.zip)

解压后，Chrome / Edge 的扩展管理页面打开开发者模式，加载含 manifest.json 的 `wangshen-main` 文件夹。现有用户更新时保持原插件安装目录不变，先备份资料，再将源码覆盖到原目录并重新加载扩展。交给本地 Codex 时直接打开该文件夹，先读 AGENTS.md。

仓库首页 `main` 就是当前版本，无需切换开发分支。源码 ZIP 包含开发说明和有效测试；纯安装包可运行 `npm run pack` 生成，排除测试、开发工具和个人资料。

## 支持的平台与填写方式

适配平台使用各自的字段结构、字典和写入方式；其他网站使用 `src/fallback/` 中的模拟点击流程。填写结果会读回核对，失败项可单独导出脱敏诊断。

| 平台 | 页面和填写方式 |
|---|---|
| Moka（app.mokahr.com） | 读取组件字段并使用平台格式写入 |
| 北森（*.zhiye.com） | 读取组件字段并使用平台格式写入 |
| Hotjob（wecruit.hotjob.cn 及同款公司域名） | 读取简历编辑器状态；学校、专业等按网站字典处理 |
| 前程无忧 51job 经典录入页（FillInResume.aspx） | 按当前分步页面读取字段；处理联动下拉和只读日期输入 |
| 前程无忧 51job 新版简历页（consumer/pc/resume） | 卡片式 Vue 编辑器；展开后读取字段，写入后读回核对 |
| 飞书招聘（*.jobs.feishu.cn） | 读取表单组件字段并使用平台格式写入 |
| 其它网站 | 使用模拟点击流程，诊断可记录失败字段 |

### 前程无忧 51job 两种页面

新版简历页（`job51v`）按卡片生命周期工作：先展开卡片，再处理“是否有经历”等条件开关，随后重新读取可见字段、编码并写入，最后读回核对。已有的多条经历卡片可以同时展开多个编辑器；新增条目时网站一次只提供一个新增表单。插件不替用户保存卡片。保存当前新增条目后再次填写，插件会继续处理下一条资料，并不表示所有条目已经自动保存。

经典录入页（`job51`）按步骤逐页处理，使用当前可见的页面标题（通常是 `h1`）识别步骤。省市等联动字段按网页实际选项和字典值填写；学校、专业使用网页提供的真实字典；只读日期输入在不触发日期选择器的情况下写入。教育经历字段名称末尾的数字用于对应资料中的相应条目。

## AI 用在哪里（以及不用在哪里）

- **不让 AI 改代码、不让 AI 编值**：复杂控件靠平台适配（读组件、写原始值、读回核对），AI 碰不到。
- **认题**：资料里没对上的选择/填空题，AI 只能从固定清单里选“对应资料哪一项”或“没有”，值仍由插件从资料取；
  经历/家庭块里的题只能选该块的属性。结果存成规则（设置页可看可删），同一网站/租户、页面类型与字段下缓存认题结果。
- **开放题**：自我评价、应聘原因等多行文字，AI 依资料写。
- **挑选项**：资料有值但网页选项叫法对不上（C1 → C照、前10% → 前20%），AI 只在网页给的选项里挑。

## 填写流程（workflow/engine.js）

1. 认平台 → 列出全部字段（id、块、第几条、类型、选项、当前值）
2. 资料能直接对应的（平台字段表 → 问题文字规则表）立刻编码写入；对不上的**同时**交给记忆/AI，不挡前者
3. 选项对不上（资料“C1”、选项“C照”）请 AI 在选项里挑
4. 批量写入 → 读回核对 → 报告；需要人工处理的在页面上描橙框
5. 没对应上的、写失败的、靠 AI 回答的字段记进诊断

专用模块未解决的字段可走唯一定位的通用字段兜底，不会重新填写整张表。默认只补空白；网页已有、但和资料不一致的值单独列出，点“用资料覆盖”只改那几项；勾“覆盖网页上已有的内容”才全部重填。
永远不点保存、提交、投递。

## 怎么成长（遇到填不好的网站）

1. 在该网页的面板里点 **导出诊断**，得到一个 JSON（只有字段 id、类型、问题文字和失败原因，没有你的资料）
2. 开发时：
   - 已适配平台、只是某个字段没对应上 → 在 `src/adapters/<平台>/mapping.js` 的字段表或 `core/mapping.js` 的规则表加一行
   - 新平台 → 抓真实申请页的字段清单放进 `test/cases/<平台>/`，写 `src/adapters/<平台>/page.js`（列字段、写原始值）和 `src/adapters/<平台>/mapping.js`（对应和格式），在 catalog.json 登记并运行 npm run sync
3. 在 `test/core.test.mjs` 加断言：这个字段应对应到什么、写成什么格式
4. 回真实页面验证：只填写，不保存不提交

**不写模拟页面做回归**：以前的测试页是照想象写的，全绿也说明不了真实网站能不能填（2.x 的教训）。

## 测试

```bash
node --test        # 在项目根目录运行：对应关系、值格式、地区编号
```

页面侧适配器只能在真实申请页上验证（需要登录）：每次改动 `src/adapters/<类型>/page.js`，都要在对应平台的真实页面上列一次字段、写一次、读回核对。

开发时：`python3 tools/devserver.py` 起本机开发服务（127.0.0.1:8765）。在开发页上派发 `af:dev-reload` 事件即可让插件
自己重新加载（不用去扩展页点）；`af:dev-msg` 可读写插件存储，用于测试前快照、测试后还原。这两样只认本机开发页。
`/form` 是一个不属于任何平台的普通表单，用来确认兜底引擎没坏。

## 安装 / 打包

- 开发：`chrome://extensions` → 开发者模式 → “加载已解压的扩展程序” → 选本目录。改代码后点该插件的“重新加载”，再刷新网申页面。
- **更新时保持插件文件夹路径不变**：原扩展继续使用它的 `chrome.storage.local` 数据。若要更换路径或换电脑，先在“资料与设置 → 备份与迁移”导出完整备份。
- 给别的电脑：运行 `python3 tools/pack.py`，生成的分发包只含 `manifest.json`、`README.md`、`icons/`、`src/` 和安装说明，不含 `data/`，也不会从安装包自动导入或覆盖个人资料。`--no-data` 为兼容旧命令，效果相同。
- 导入会完整替换本机资料与设置，导入前会保存本机数据，可用“撤销上次导入”恢复一次。

## 数据和迁移

3.9 继续使用 3.8 的个人资料、记住的回答、学习规则及其历史、资料补充、附件、设置和运行缓存保存在浏览器的 `chrome.storage.local`。分发代码包不包含 `data/`，安装后不会自动导入或覆盖个人资料。完整备份包含 `profile`、`answers`、`memories`（含 `history`）、`supplement`、`files`、`settings`（含已设置的 API Key；导出时默认勾选）、`resume`、`photo`、`cache`、`picks`、`profileRev` 和 `seedVersion`。导入执行完整恢复，缺失项目使用默认空值；导入前的数据可撤销一次。取消 API Key 勾选时，导入会清空目标设备的 API Key。

网站诊断记录不放进个人数据备份；在“网站诊断”页单独导出脱敏诊断文件。

以下是主要存储键：

| 键 | 内容 |
|---|---|
| `profile` | 资料，在“资料与记忆”页编辑 |
| `answers` | 你亲手改过并点“记住”的回答，优先于 AI |
| `memories` | 学到的规则，保留规则历史 |
| `supplement` | 网页补答形成的资料补充 |
| `files` / `resume` / `photo` | 附件、旧版单独存放的简历和证件照 |
| `settings` | AI 接口、模型、API Key 和其他设置 |
| `cache` / `picks` | AI 回答与选项选择缓存 |
| `profileRev` | 资料版本标记，用于关联缓存 |
| `diag` | 独立诊断记录；导出时脱敏，不随个人数据备份迁移 |

身份证号、电话、邮箱不发给 AI：发送前换成占位符，回填时在本地还原。
